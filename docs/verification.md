# 검증 기록

## 자동 테스트

2026-11-12 기준 `npm test`를 실행했습니다. Vitest 5.1.0 + Supertest 결과는 **19 tests passed**입니다. `npm audit` 결과는 취약점 0건입니다. 일부러 실패시키는 롤백 테스트에서는 예상한 SQLite 오류가 stderr에 찍힐 수 있으며, 해당 테스트 자체는 통과합니다.

SQLite 드라이버(`node:sqlite`)가 동기식이므로 `Promise.all` 검증은 실제 DB 경합을 재현하지 않습니다. 요청이 동시에 들어오는 형태의 호출에서 정원 재검사 후 한 건만 반영되는지를 확인하는 수준이며, 다중 프로세스 부하 테스트는 수행하지 않았습니다.

## 시드 및 수동 확인

`npm run db:reset`은 데이터베이스 파일을 삭제하고 데모 데이터를 새로 만듭니다. 초기 데이터에는 다음 세 스터디가 포함됩니다. 기존 운영 DB는 초기화하지 않고, `npm run db:seed:demo`로 중복 생성 없이 시연 글을 추가할 수 있습니다.

| 시연용 항목 | 준비 상태 | 시연 동작 |
| --- | --- | --- |
| 알고리즘 스터디 | 정원 2, 승인 멤버 1명 | 남은 한 자리 지원·승인 |
| 정원 초과 시연 스터디 | 정원 1, B와 C 대기 | C 승인 후 B 승인 시도, 409 확인 |
| 라이브 지원 시연 스터디 | 모집 중, 빈 정원 | 영상에서 다른 계정으로 새 지원 |

데모 계정은 `leaderA`, `leaderB`, `memberC`이며 초기화 명령이 공통 비밀번호를 출력합니다. 현재 운영 DB에는 `db:reset`을 실행하지 않았습니다. 해당 명령은 기존 데이터를 삭제하므로, 새 데모 행을 라이브에 추가할 때는 비파괴적 시드 절차가 필요합니다.

사용자가 확인한 JCloud 수동 결과: 서비스가 활성 상태이며 `curl http://127.0.0.1:3000/api/health` 응답은 `{"status":"ok"}`였습니다. 사용자는 공개 URL에서 화면 표시와 로그인을 확인했습니다. 최신 코드 배포 후 서버에서 자동 테스트 19개가 통과했고 서비스 재시작 후 health 응답도 정상이었습니다. 제출 직전에는 다른 네트워크의 계정으로 지원→승인→작업 변경 전체를 다시 수행하고 화면 캡처를 기록해야 합니다.
